Everything on this site is a page, and every page lives in one of a
few folders. Once you know what each folder is *for*, you can always
guess where something is.

| Folder | What lives there | When you go there |
| --- | --- | --- |
| All Classes | One page per class: agenda and to-dos | You were away, or forget what is due |
| Concepts | The ideas, stated cleanly | After class, when you want it precise |
| Warm-Ups | Our daily five-minute routines | You want the rules, or extra reps |
| Explorations | The activities we think our way through | Before, during, and after we work them |
| Exercises | Practice sets, answers folded underneath | You want to test whether it stuck |
| Programs | Complete programs to read, run, and change | You want to see real code doing real work |
| Tasks | The projects, with their success criteria | Before, during, and after any task |
| Discussions | The arguments we keep returning to | Preparing to talk, or thinking afterwards |
| Portfolios | Your Code Journal and its guides | Log time, and the end of each unit |
| Tutorials | How-to skills for the course | The moment a how-do-I question hits |
| Setup | Routines, norms, marks, help | Your first week, then whenever |
| Style | Pages about the site itself | You wonder why pages look this way |

## The site is a web, not a filing cabinet

The folders are only half the organisation. The other half is
**links**: a concept links to the programs that show it running and
the practice that tests it, and the *Backlinks* panel at the bottom
of any page shows everything pointing the other way. Open
[[Recursion]] and its backlinks name every place in the course that
leans on it. Nobody maintains that list by hand.

That panel is worth a second look this year, because it answers a
question you will be asking constantly about real code: **what
depends on this?** Before changing a shared function, you want to
know everything that calls it. A site that gives you that in one
glance is good practice for a codebase that will not.

Start anywhere and follow the thread. That is not a workaround for
bad filing — it is closer to how the ideas actually relate to each
other than any folder tree could be, and it is the same reason a
well-organised project has a README that links outward rather than a
folder called `docs` that nobody opens.
