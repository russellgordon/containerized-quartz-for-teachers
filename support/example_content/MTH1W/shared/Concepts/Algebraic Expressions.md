When your group described figure $100$ of a [[Visual Patterns]] talk
without drawing it — "four arms of $n$ tiles plus one in the middle" —
you were already writing $4n + 1$; the symbols just came later. An
algebraic expression is a *generalisation*: one sentence that answers
every "how many at step $n$?" question at once. Different ways of
seeing the same pattern produce different expressions — one group's
$4n + 1$ is another's $4(n + 1) - 3$ — and both can be right. That is
not a problem to fix; it is the next question to ask.

## Equivalent, or just look-alike?

Two expressions are **equivalent** when they agree for *every* value
of the variable — they are two descriptions of one quantity. There are
four honest ways to compare them, and each can settle a whiteboard
argument:

- **Numerically** — substitute values. One disagreement proves the
  expressions are different; agreement on a few values is evidence,
  not proof.
- **Concretely** — build both with algebra tiles and see whether the
  arrangements match up.
- **Graphically** — graph both in [[Using Desmos]]; equivalent
  expressions produce the same graph, exactly.
- **Algebraically** — simplify both using properties you already
  trust, and see whether they land on the same form.

> [!success]- Quick self-check (click to expand)
> Is $4(n + 2)$ equivalent to $4n + 2$? Try $n = 1$: the first gives
> $12$, the second gives $6$. Different — one counterexample ends it.
> Is $4(n + 2)$ equivalent to $4n + 8$? The distributive property says
> four groups of $(n + 2)$ means four $n$s *and* four $2$s, so yes —
> and no substitution can ever break it.

Simplifying is not about making expressions shorter for tidiness; it
is about revealing that two descriptions were secretly the same one.
[[Expression Practice]] builds the skills, [[Pattern Machines]] asks
you to design patterns whose rules others must find, and
[[Coding Visual Patterns]] turns your expressions into running code
that tests thousands of values in a blink.
